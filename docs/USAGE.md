# 使用指南

本文说明管理台的日常操作、资料模型、上传规则、AI 识别、搜题和状态含义。安装与配置见 [DEPLOYMENT.md](DEPLOYMENT.md)，接口字段见 [API.md](API.md)，技术数据流见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 首次使用

1. 使用首次启动时配置的管理员账号登录。
2. 在「用户」中创建 `editor` 或 `viewer` 账号，按需分配权限。
3. 原件上传后即保存在本机，不配置网盘也能归档、下载和搜题。需要网盘副本时，在「存储 → 网盘」中添加网盘并测试连接。
4. 在「存储 → 同步规则」中决定哪些文件上传到哪些网盘、放在什么目录，预览后保存。
5. 在任意页面点击「导入资料」开始归档。

## 2. 资料模型

| 对象 | 作用 |
| --- | --- |
| 套卷 | 浏览和编目单位。学科、年级、届别、地区、机构、类型、标签和描述保存在套卷上 |
| 文件 | 一份逻辑内容。记录部件、答案起始页和在套卷中的顺序 |
| 源记录 | 同一内容从不同导入路径到达时追加来源，不复制原件 |
| 专题 | 把套卷按复习主题重新组合，不改变套卷内容 |
| 回收站 | 保存已删除的套卷和文件 30 天，可恢复或彻底删除 |

文件部件包括试题、答案、教师版、答题卡、听力和正文。文件从所属套卷继承编目信息。编目全部由 AI 决定；人工修改过的字段（包括标题和文件部件）会被锁定，之后 AI 不再改动。

学校、联盟和标签保存在「名称词典」中：同一所学校只有一个规范名称，文中出现的简称、旧称、带不带省市前缀等写法都是它的别名。AI 编目时优先选用已有名称，只有确认是新机构时才新建，并会检查新名称是否与已有名称重复。

同一 SHA-256 只归档一次。重复上传会显示为秒传或追加来源记录，不重复解析、索引和上传网盘。

## 3. 上传与归档

### 选择内容

- 文件夹中的文件逐个传输并保留相对路径。
- 哪些文件属于同一套由 AI 根据内容判断：同一批上传的文件读完后一起分组，也会与资料库中已有的套卷比对（例如后上传的答案会归入已有的试卷）。文件夹和文件名只作为旁证。
- ZIP 由服务端安全展开，成员按展开后的路径参与分组；ZIP 原件本身不进入资料库。
- 支持上传 PDF、DOC、DOCX、PPT、PPTX、XLS、XLSX、常见图片和音频；文件真实格式必须与扩展名一致。

选择完成后会立即创建上传清单并开始传输，无需先填写完整表单。可选的批次提示（类型、学科、年级等）只作为 AI 的参考，不会直接写入编目。

### 上传限制

- 一个清单最多 2000 个文件。
- 单个文件最大 512 MiB。
- 一批文件总大小最大 2 GiB。
- 每个 ZIP 最多展开 5000 个非忽略文件，声明展开总大小不超过 2 GiB。
- ZIP 中只归档 PDF、DOC、DOCX、PPTX 和嵌套 ZIP；其他成员会跳过并提示。
- 整个 ZIP 链最多展开 3 层；超过上限的嵌套包按不支持成员跳过。

服务端拒绝路径穿越、绝对路径、符号链接、重复路径、加密 ZIP、格式伪装和解压炸弹，并尝试还原 GB18030、Big5 或 Shift-JIS 文件名。

全部文件接收后会自动提交归档。关闭页面或网络中断时，可在「导入中心」中重新选择未完成文件或重试失败项；已接收内容无需重传。

### 归档后

归档后，AI 依次阅读每个文件、把同一批文件分组成套、确定每套的编目，通过校验后自动入库并开始网盘同步。这些步骤与题目索引、网盘同步都是独立任务，失败不会影响原件归档与下载；暂时性失败会自动重试。

文件详情支持下载原件，预览 PDF 和 DOCX。DOCX 首次预览或「下载 PDF」会由服务端转换并缓存；复杂版式、公式和缺失字体可能与 Word 显示不同，加密文档和外部引用资源需要先在本地处理。

## 4. 整理资料库

- 「需关注」只列出 AI 没能通过校验的套卷，并给出具体原因（例如部件重复、缺学科或年级、没有读到正文、分组未能确认、AI 多次失败）。可以直接确认、修改后确认，或在套卷的「AI 编目」中让 AI 重新编目。「AI 整理中」与「等待 AI」两个标签页显示仍在处理或等待 AI 配置的套卷。
- 「资料库」可按编目字段筛选套卷，查看文件、预览原件、调整顺序、批量编辑或打包下载。
- 移动文件、拆分或合并套卷后，AI 会重新确定相关套卷的编目，人工修改过的字段保持不变。
- 「名称词典」列出所有学校、联盟和标签的规范名称及别名。AI 弄错时可以改名、合并或移除别名；修改过的条目会锁定。
- 「专题」只建立套卷收录关系。删除专题不会删除套卷；合并套卷时已有专题收录会保留。
- 删除套卷或文件会进入回收站。彻底删除会清理文件、来源、专题收录、解析缓存、题目索引和 `local` 网盘中的文件；云盘上的文件不会自动删除，而是转为「规则外」副本，可在「存储 → 副本」中删除或保留。

## 5. 网盘同步

网盘同步由三部分组成：

| 概念 | 作用 |
| --- | --- |
| 网盘 | 描述连接方式和上传路由：类型、凭据、根目录、单文件上限、允许的扩展名、读取顺序、路径变化策略，以及主端/从端优先级 |
| 同步规则 | 有序列表，自上而下匹配，**命中第一条为止**；条件可按学科、类型、年级、届别、地区、标签、部件、格式和大小组合。每条规则可指定多个目标网盘及路径模板、是否分享、是否必需 |
| 副本 | 每个「文件 × 网盘」一条，记录期望路径、实际路径、上传与分享状态 |

列表最后固定有一条「其他所有文件」兜底规则。新系统里它没有目标，即默认不上传任何网盘。

### 配置

1. 在「存储 → 网盘」中添加 WebDAV、OneDrive、S3、蓝奏云或本地目录，填写根目录并测试连接。123 云盘目前只能探测连接，不能作为同步目标。
2. 编辑远程网盘的「上传节点路由」，选择自动分配、按优先级故障切换或仅使用指定节点，把主端或从端按优先级加入列表。优先级数字越小越先上传；`local` 网盘不能配置从端。
3. 在「存储 → 同步规则」中新建规则或编辑兜底规则，为目标网盘填写路径模板，默认 `{学科}/{届别}/{类型}/{套卷}/{文件名}`。模板必须以 `{文件名}` 结尾；蓝奏云不支持子目录，只使用文件名。
4. 点击「预览并保存」。预览会列出新增上传、移动、补分享、规则外和跳过的数量与明细，确认后才写入规则并生成任务。预览后如果其他人改了规则或网盘，需要重新预览。

修改网盘设置不会自动作用到已有文件；需要时点击存储页右上角的「补齐副本」，按当前规则重新规划全部已编目文件。

### 同步时机

- 规则依赖编目，所以文件在 AI 确定所在套卷的编目后进入同步计划；需关注的套卷也会按当前编目同步，之后的修改会按网盘的路径策略移动。只有 AI 多次未能编目的套卷暂不同步，人工确认后进入。
- 等待期间同步状态显示「等待编目」，文件详情可点击「按当前编目同步」立即进入计划。
- 改名、修改编目或部件会自动重新计算该文件的路径；路径变化时，设置为「移动」的网盘会在远端移动或改名，设置为「保持原位」的网盘会标记「路径偏离」。
- 上传从不覆盖网盘上已有的不同文件；目标路径被占用时任务失败为冲突。

### 规则外副本

规则修改或资料彻底删除后，不再需要的云端文件会标记为「规则外」，系统不会自动删除。在「存储 → 副本」中按状态筛选，可以批量删除远端文件、只移除记录或重试失败副本。

## 6. AI 编目

编目只由 AI 决定：AI 阅读文件、把文件分组成套、确定每套的类型、学科、年级、届别、学期、地区、学校/联盟、考试名称和标签，以及每个文件的部件。程序规则只用来检查 AI 的回答是否可靠，不替 AI 做判断。

### 配置

1. 管理员在「AI 模型」中添加 OpenAI 兼容端点，填写 Base URL 和 API Key，并运行探测或最小对话测试。
2. 在「AI 解析」中选择 OCR 服务商。
3. 自建 Compose 推荐使用 `RapidOCR（自建）`，地址为 `http://rapidocr:9003`，无需令牌。
4. PaddleOCR 和 MinerU 需要填写各自服务地址与令牌。

没有可用的模型或 OCR 时，新文件照常归档、可下载，整理状态显示「等待 AI」；配置保存后自动继续。存储、AI 和 OCR 凭据使用 `MASTER_KEY` 加密保存；接口只返回是否已配置，不回显密钥。

### 三个步骤

1. **阅读**：AI 读取每个文件的正文（或页面图像），记录它是什么部件、首页标题、学科、年级、学年、考试年月，以及文中出现的学校和地区写法。年级、学年、届别、考试年月和标题必须附原文摘录，摘录在原文中找不到的值会被剔除。音频、表格或读不出正文的文件只依据文件名和路径判断，并在需关注中提示「未读到正文」。
2. **分组**：同一批上传的文件读完后，AI 把它们分成套卷，并与资料库中可能相关的套卷比对；同一套中试题卷、答案、答题卡等各最多一份，不同学科不会放进同一套。
3. **编目**：AI 看到整套文件后确定编目。学年与届别必须一致，考试年月必须落在学年内，学期由考试月份推算，地区只能取固定列表；学校优先使用名称词典中的已有名称，新学校必须写完整正式名称。人工修改过的字段保持不变。

每一步的回答没有通过检查时，AI 会按问题清单修正一次，仍不行再换下一个模型；关键问题仍未解决的套卷进入「需关注」，其余不可靠的值直接剔除。模型的“自信程度”不参与判断。

### 查看与调整

- 文件详情的「AI 阅读记录」显示读到的信息、原文依据和被剔除的值，可以「重新阅读」。
- 套卷详情的「AI 编目」显示整套决定与校验结果，可以「重新编目」。
- 「AI 解析 → 重新整理已有资料」可让需关注的或全部资料重新经过 AI：只重新编目，或重新阅读、分组并编目（已解析的正文会复用）。执行前先预览涉及的文件数和预计调用次数。

RapidOCR 可直接读取 DOCX 的段落、标题、表格、文本框、公式和分页提示，并对嵌入图片执行 OCR。图片有数量和体积上限；单张图片失败不会丢失正文。页码来自显式或渲染分页，没有分页提示的连续文档按第 1 页处理。

系统不会自动创建专题，也不会自动改写套卷的专题归属。

## 7. 搜题

「搜题」输入题干或公式后，会返回题目、命中高亮、页码、原试卷和所属套卷。PDF 可打开并定位到对应页；非 PDF 原件跳转到文件详情。

索引默认启用，但需要可用的 OCR 与模型。只有部件为“试题”或“试卷+答案”的文件会自动入队；部件变化后，系统会同步创建或清理索引。关闭索引期间归档的试卷文件会在重新启用后补建。

公式搜索支持常见文本和 LaTeX 写法，例如 `x+y`、`x²+1`、`x^{2}+1` 与 `\frac{x}{y}`；支持符号写法归一化，不进行通用代数等价推导。当前 RapidOCR 未接入扫描件公式识别模型。

文件详情的「题目索引」可查看题目、页码、置信度和状态。索引失败不影响归档与下载；重建失败时旧索引仍可查询。

## 8. 角色、状态与任务

| 角色 | 主要权限 |
| --- | --- |
| `admin` | 全部权限，包括用户、密钥、存储、AI、审计和系统配置 |
| `editor` | 读写套卷、文件、专题，导入资料并查看任务 |
| `viewer` | 只读套卷、专题和任务 |

API 密钥的有效权限是密钥授权范围与所属用户当前角色权限的交集。撤销密钥或禁用用户后，后续请求立即失效。

常见上传状态：

```text
pending → processing → completed / failed
```

文件整理阶段：

- `processing`：AI 整理中（阅读、分组或编目）。
- `waiting_ai`：等待 AI（没有可用的模型或 OCR，配置后自动继续）。
- `attention`：需关注（AI 没能通过校验，需要人工确认或修改）。
- `ready`：已入库。

归档状态只表示原件是否安全：

- `archived`：原件在本机。
- `missing`：本机原件缺失，只能从网盘副本读取。

同步状态单独表示网盘进度：

- `waiting_catalog`：等待编目确定。
- `not_required`：命中的规则不上传任何网盘。
- `syncing`：正在上传或移动。
- `synced`：所有必需目标已就绪。
- `attention`：必需目标失败、分享失败或路径偏离，需要处理。

副本状态为 `pending`（待处理）、`uploading`（上传中）、`moving`（移动中）、`ready`（已就绪）、`failed`（失败）、`skipped`（已跳过：网盘停用、超过大小上限或扩展名不允许）和 `orphaned`（规则外）。

任务状态为 `pending → running → succeeded / failed`。在「处理日志」中可查看归档、复制、AI 阅读、分组、编目、名称去重和索引进度。暂时性失败会自动按 1 分钟到 12 小时的间隔重试，最多 6 次；具有 `jobs:write` 权限的用户可以重试单个或全部失败任务。

## 9. 节点

管理员可以在「系统 → 节点」查看主端和从端的状态、CPU、内存、网络和任务数，点开一行查看最近 1 小时的趋势和正在执行的任务。

- **集群调度**：节点页顶部的「集群调度」控制主端是否执行复制、AI 分析和索引，以及主端四类并发、任务租约、心跳、领取等待和空闲轮询。保存后主端立即应用，从端在下一次心跳应用。
- **添加节点**：创建时直接设置复制、分析、索引槽位，原件缓存上限，以及该节点可访问的 RapidOCR、PaddleOCR 或 MinerU 服务。保存后只显示一次接入令牌，到从端机器上启动，步骤见 [主从节点](DEPLOYMENT.md#6-主从节点)。
- **修改节点配置**：在列表的「配置」或节点详情的「运行配置」中修改。节点显示“等待应用”时表示主端已保存、从端还没完成下一次心跳；显示“已应用”后才代表远端运行时已切换。
- **OCR 调度**：一个节点可以选择多个 OCR 服务；主端按「AI 解析」中的服务优先级选择，不会把从端解析不了的服务交给它。
- **排空**：节点不再领取新任务，手上的任务继续跑完。
- **停用**：节点令牌立即失效，手上的任务停止，并在租约到期后交给其他节点。

处理日志中的「执行节点」显示任务在哪台机器上运行，也可以按节点筛选。

## 10. 观测与 Agent 接入

顶栏「网络」在浏览器会话内采集最近的 API、上传和下载请求，显示 P95、平均值、中位数、成功率、传输量、在途请求、响应大小和 request ID。采样只存在内存，不记录正文、凭据或查询参数。

后端日志对每个 `/api/*` 和 `/mcp` 请求记录方法、路径、状态、耗时、响应字节数和 request ID，不记录查询参数、请求体或响应正文。

管理员可为 Agent 创建最小权限 API 密钥。REST 和 MCP 都使用 `Authorization: Bearer <密钥>`；密钥明文只在创建时显示一次。MCP 客户端配置、工具和上传下载方式见 [MCP 接入指南](MCP.md)。
